## 执行方式

构建使用 Zulu JDK 25.0.4.1。Java 17 矩阵使用临时安装的 Temurin 17.0.20.1；Gradle 不需要修改系统默认 Java。Netty 测试均启用 `PARANOID` 泄漏检测。

```bash
./gradlew test -PtestJavaVersion=25 -PnettyTestVersion=4.2.7.Final --rerun-tasks
./gradlew test -PtestJavaVersion=17 -PnettyTestVersion=4.1.68.Final -Dorg.gradle.java.installations.paths=<JDK17绝对路径> --rerun-tasks
./gradlew :velozip-backend:test :velozip-common:test -PtestJavaVersion=25 -PnettyTestVersion=4.1.50.Final --rerun-tasks
./gradlew build -PtestJavaVersion=25 -PnettyTestVersion=4.2.7.Final
```

两组完整矩阵均实际重跑。旧 Netty 的 61 项结果来自同一提交在上一轮同步验证中的实际重跑，本轮未再次重跑该组。最后一次 `build` 的测试任务从 Gradle 缓存恢复，成品打包及 `verifyArtifacts` 实际执行。

`verifyArtifacts` 检查后端基础 class major 不超过 60、代理不超过 61，后端 `api-version: '1.16'`，描述文件和代码版本一致，平台类未被打包，SnakeYAML/HdrHistogram 已隔离且 zstd JNI 绑定存在。此检查不等价于在 Java 16 上启动插件。

以下脚本分别通过 `node --check`：`e2e.mjs`、`e2e-matrix.mjs`、`e2e-evidence.mjs`、`test-evidence.mjs`、`legacy-bot.mjs`。语法检查未执行脚本的服务器交互和证据导出逻辑。

## 限制与观察

- 本轮未找到可执行 E2E 所需的本地代理/后端 jar 和 fixture，因此没有验证真实登录、协商激活、重连、双向流量或回退路径。历史 [v1.0.0 E2E 报告](E2E-1.0.0.zh-CN.md)只适用于历史构建。
- 1.16/1.17 版本识别、候选连接类名及旧 Netty 单元测试不能证明具体 Paper/Purpur 构建兼容。Java 16 运行时也未验证，不应将这些目标列为已实测平台。
- 现有 `recognizesLegacyVersionedTypeNames` 测试仅检查普通 Channel 字段查找，未走真实版本化 NMS 类型的完整玩家连接链；新增类名仍需独立接口核验或真实 E2E。
- Java 25 下出现 JNI 原生访问提示；编译有现有未检查类型操作提示，构建有 Gradle 10 弃用提示，均未使本次验证失败。
- 本轮测试基于已包含时间窗口断言调整的提交。延时批次用例通过不代表精确验证了最小延迟或性能上限；本轮没有新增性能结论。

本报告依据本地命令完成状态和 JUnit 汇总编写，未新增逐组归档的原始结果。Gradle 切换测试矩阵会覆盖本地报告；仓库 `docs/tests/v1.0.0/` 中的 JSON 仍为历史证据，未用本轮结果覆盖。
