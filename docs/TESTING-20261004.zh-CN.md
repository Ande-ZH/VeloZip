## JMH 基准复测（当前源码）

按 [BENCHMARK.md](BENCHMARK.md) 相同方法论（`-wi 2 -i 3 -f 1 -t 1`，JDK 25 / Zulu
25.0.4.1，zstd-jni 1.5.7-15）在当前源码重跑。关键结果（compress-only，µs/op）：

| size | RANDOM | COMPRESSIBLE | MC_LIKE |
|---:|---:|---:|---:|
| 128 B   | 1.11 | 2.86 | 1.52 |
| 1 KiB   | 2.87 | 11.67 | 4.99 |
| 4 KiB   | 5.42 | 20.41 | 11.54 |
| 16 KiB  | 12.10 | 91.90 | 20.26 |
| 32 KiB  | 20.82 | 117.54 | 28.17 |
| 64 KiB  | 16.58 | 278.95 | 67.56 |

批处理 round trip（吞吐模式）：32 KiB ≈ 83,066 ops/s（约 12.0 µs/op）、
64 KiB ≈ 39,216 ops/s（约 25.5 µs/op），与既有" tens of microseconds"结论一致。

原始 JMH JSON：[docs/benchmarks/v1.0.0-20261004/results.json](benchmarks/v1.0.0-20261004/results.json)。
本轮在共享的双核虚拟机上执行，置信区间明显宽于历史数据（如 COMPRESSIBLE 64 KiB
±349 µs）；数值仅作方向性对照，不替代部署硬件上的实测。

## 边界与未覆盖

- E2E 仅覆盖 **Purpur 1.16.5-1171** 与 **Paper 1.17.1-411** 两个精确构建；
  1.16.1/1.16.4、1.17.0 等其他构建未实测，支持系列不等于系列内全部构建已验证。
- 本轮未包含重连用例与 ViaVersion 转换组合，也未做长稳/负载测试；
  1.18–26.2 的本轮回归依赖单元测试与历史 E2E 证据（历史证据只适用于当时构建）。
- `legacy-bot.mjs` 客户端覆盖登录、位置应答与保持，不等同真实客户端的全部包行为。
- Java 16 矩阵的导出 JSON 由 Gradle 缓存恢复生成（首次实际执行同为 2026-10-04，
  见上文）；如需强制重跑可加 `--rerun-tasks`。
