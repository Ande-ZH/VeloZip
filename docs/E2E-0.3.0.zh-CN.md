# VeloZip 0.3.0 隔离端到端实验（2026-09-07）

## 范围与结论口径

本轮使用提交 `6a3065bc2393027d34183824a7c77a8e163bfc64` 的既有 0.3.0 成品，传输协议仍为 **v1**。只修改实验脚本与 bot 夹具，不修改产品实现、不重新打包插件。实验日期按本地 UTC+08:00；JSON 时间使用 UTC，因而显示 2026-09-06 晚间。

所有服务在仓库 `build/e2e-*` 新建目录运行，每个矩阵项创建新世界，仅监听 `127.0.0.1` 临时端口。只复制既有测试目录中的运行库/cache/versions；不复制世界、配置或既有插件目录。不修改或连接共享 Minecraft 服务，不修改系统 Java/Node 默认指向。矩阵串行，每次最多一个后端、一个代理、一个 bot，后端堆上限 1200 MiB、代理 512 MiB。结束只向本次 spawn 的子进程发送 TERM，5 秒后仍存活则 KILL，再确认退出。原始本地日志不删改，不公开配置中的随机转发密钥/认证密钥。

**通过不等于生产认证**：正向项必须 bot 收到 PLAY 登录包、从 PLAY 开始持续连接至少 30 秒、正常退出码 0、两端每次都出现激活日志、在线采样两端 `Active connections: 1`。负向项按明确预期判断，不能把“没有激活”当正向成功。退出后的统计用于量化和双边对账，不以单条激活日志代替实际传输。

## 夹具修正与方法

旧 bot 的计时从 connect 后开始，不能严格称为 15 秒 PLAY 保活。本轮改为最多等待 PLAY 30 秒，然后使用单调时钟保活 30 秒，输出实际毫秒数；提前断连/未进入 PLAY 返回 1。旧版预跑三次重连日志保留在本地，但不纳入正式表格。正式矩阵均使用重编译后的同一 bot class，源码及 class SHA-256 在 `e2e/v0.3.0-20260907/fixture.json`。

- 客户端：MCProtocolLib `1.21.11-1`（774）或 `26.1-1`（775），静止离线 bot，仅登录、自动协议应答、接收区块和世界更新、保活、主动断开；不模拟玩家移动/挖掘，不做多人负载。
- Java：1.21.11 后端用私有 Zulu Java 21；26.x 后端、所有代理和 bot 用 Java 25。精确 `java -version` 和执行文件哈希见每项 JSON。
- 世界配置：`level-name=fresh-world`、`level-type=minecraft:flat`、不生成结构、视距/模拟距离均 3。没有固定 seed，没有显式 flat generator-settings；启动实际记录 `No key layers in MapLike[{}]` 并继续使用服务器回退处理。因此不声称世界内容逐字节相同，也不把这些数字当严格 A/B 性能比较。
- VeloZip 使用默认 Zstd level 1、RAW 阈值 128 B、batch 最大 65536 B、最大延迟 500 µs、frame 最大 1048576 B、解压最大 2097152 B。认证拒绝项才配置两端不同的随机认证密钥；现代转发密钥每个运行随机生成且两端一致。
- 服务启动完成后、bot 启动约 10 秒时、bot 退出并静置 2 秒后，通过自己进程的 stdin 执行 `velozip status`、`velozip stats`、`velozip config`；代理还执行 `velozip servers`。每轮等 1.5 秒收集输出。无插件一端不执行插件命令。
- 三次重连是同一 isolated server/world、同名 bot 依次重新登录；不是快速跨服切换。每次退出后采样，下一次再登录，检验 active 回归零、重新激活、累计计数。

### 实际应用层帧字节

下表均取最后一次断开后静置快照，使用**代理视角**；`original → wire` 单位 B。6 项的 backend TX 与 proxy RX、backend RX 与 proxy TX 的 original/wire/RAW/ZSTD 计数全部精确相等；在线快照则可有正常异步差值。

| 项目 | 代理 TX original → wire | 代理 RX original → wire | 合计 original → wire | 应用层帧字节节省率 |
|---|---:|---:|---:|---:|
| paper121-reconnect（3 次累计） | 880 → 1320 | 1938199 → 192040 | 1939079 → 193360 | 90.03% |
| paper261 | 300 → 450 | 602550 → 17621 | 602850 → 18071 | 97.00% |
| paper262-via | 300 → 450 | 679566 → 94353 | 679866 → 94803 | 86.06% |
| purpur121 | 290 → 435 | 659006 → 78405 | 659296 → 78840 | 88.04% |
| purpur261 | 300 → 450 | 685764 → 98020 | 686064 → 98470 | 85.65% |
| velocity340-paper121 | 300 → 450 | 670046 → 89319 | 670346 → 89769 | 86.61% |

不能从各行的差别得出平台快慢排名：随机新世界、加载/协商时机、不同协议和重连次数导致实际包集合不同。很小的上行包走 RAW，TX wire 大于 original 是真实帧头开销，不应隐藏。

### 发现而未修复的问题

- **REFUSE 状态链路失败**：正确设置两端认证后，后端明确输出 `HMAC verification failed`（code 4），但代理 5 秒后记录 `negotiation timeout`，没有 `refused (code 4)`。因此安全拒绝激活这一点成立，精确拒绝原因传递检查不成立；JSON 保留 `passed=false`，不能宣传认证完整 E2E 全通过。
- **fallback 恢复错误**：缺失插件及认证拒绝运行均出现 `VeloZip: failed to restore vanilla decoder`。允许 fallback 时 bot 仍保活且计数为零，但这不能证明 pipeline 恢复正确。现有日志没有异常堆栈，无法仅据日志确定根因；源码 `restore()` 试图重新安装先前移除的原 decoder 实例，应另行验证 Netty 非 Sharable handler 重加限制及恢复后的实际 pipeline。本任务没有加日志或改产品。
- **实验配置路径陷阱**：源码注释称 `plugins/velozip-velocity/config.yml`，实际插件 ID 的数据目录是 `plugins/velozip/config.yml`。首轮 3 个配置敏感项因此无效，其中 disabled 即使脚本输出 PASS 也被剔除。修正脚本目录后重跑，并检查控制台有效配置。默认配置的正向项不受路径差异影响。

## 指标定义与计算

已先核对 `VeloZipBatchEncoder.emitNow`、`VeloZipInbound.parseOne` 与 `VeloZipMetrics`：

1. `originalBytes` 是批次中的 Minecraft packet body 加各包内层 VarInt 长度前缀。
2. `wireBytes` 包含 VeloZip 帧头（magic/version/flags/长度）和 RAW 或 Zstd payload。
3. TX 在帧构造完成并准备提交时记账，不代表 TCP ACK；RX 在完整帧解析、解压/拆包成功后记账。
4. 在线快照的 LongAdder 不是全局原子，两端采样不是同时进行；以断开后静置快照核对 backend TX = proxy RX、backend RX = proxy TX。
5. 单端合计 `O=TX.originalBytes+RX.originalBytes`，`W=TX.wireBytes+RX.wireBytes`，**应用层帧字节节省率** `100×(1-W/O)`。不截断负值，RAW 小帧可能变大。不能把两端 TX+RX 再相加，否则重复计数。

这不是 TCP 抓包，不包含握手前 vanilla 流量、客户端—代理链路、TCP/IP 头、重传、ACK。无插件 baseline 只验证同类拓扑与 bot 能正常工作，没有可比较的 VeloZip 计数，故不发布“比 vanilla 实际带宽降低 X%”。同样没有从压缩微基准移植数字。没有稳定精确采样时间基准可算整个流量窗口的 bytes/s，故仅报告实际累计字节，不把 30 秒保活时间冒充完整计数窗口时长。

## 复现命令

以下单项命令是可移植接口；输入 jar/JDK 请自行提供对应哈希的合法下载，不能指向正在运行的共享服务目录。

```bash
JAVA_HOME=/absolute/jdk25 bash /absolute/Velozip/gradlew -p /absolute/Velozip \
  :velozip-itest:classes :velozip-itest:writeBotClasspaths --no-daemon \
  -Dorg.gradle.java.installations.paths=/absolute/jdk25

JAVA=/absolute/jdk25/bin/java BACKEND_JAVA=/absolute/jdk21/bin/java \
BACKEND_JAR=/absolute/paper-1.21.11-132.jar \
PROXY_JAR=/absolute/velocity-4.1.1-24.jar \
BACKEND_SEED=/absolute/read-only-test-cache \
BOT_TASK=botLegacy BOT_SECONDS=30 BOT_REPEATS=3 \
E2E_CASE=paper121-reconnect E2E_MODE=active \
node /absolute/Velozip/scripts/e2e.mjs
```

`BACKEND_SEED` 可省略（服务自行下载运行依赖）。`E2E_MODE` 支持 `active`、`baseline`（两端不安装）、`missing`（后端缺失并允许 fallback）、`required-missing`（缺失且强制要求，预期 bot 1）、`auth-refusal`（密钥不匹配但允许 fallback）、`disabled`（代理禁用）、`outdated`（预期客户端版本拒绝）。`BOT_TASK=bot` 选择 26.1。`VIA_JARS` 用冒号分隔绝对 jar 路径；只在 26.2 辅助项设置。

本机实际执行的完整矩阵入口，准确输入缓存路径保存在脚本中（只引用本仓库旧隔离测试缓存）：

```bash
/env/node/bin/node /project/Velozip/scripts/e2e-matrix.mjs
# 可用 CASE_FILTER=paper121 选子集，JAVA/JAVA21/PROXY_JAR 覆盖执行文件。
CASE_FILTER=missing-required,auth-refusal,proxy-disabled \
  /env/node/bin/node /project/Velozip/scripts/e2e-matrix.mjs
/env/node/bin/node /project/Velozip/scripts/e2e-evidence.mjs \
  /project/Velozip/build/e2e-matrix-1788729366139 \
  /project/Velozip/build/e2e-matrix-1788730531454 \
  /project/Velozip/build/e2e-matrix-1788731622580
```

旧 Velocity 从官方 `https://fill.papermc.io/v3/projects/velocity/versions/3.4.0-SNAPSHOT/builds` 选 build 563，按下载元数据校验 SHA-256 `fe53021f3168322cb6cb68f78699866fd098df3c306e4359847a10b0d02689ef`。其余具体输入 jar 和 Via jar 哈希、bot 依赖清单均在 JSON，无需信任缓存文件名。

## 证据、警告与未覆盖范围

公开目录 `e2e/v0.3.0-20260907/` 包含机器可读结果、配置摘要、依赖/成品/夹具哈希，以及白名单抽取的日志片段。片段不是完整原始日志；每份原日志 SHA-256 供本地核验。原始目录索引仅在本机矩阵目录 `raw-index.json`，不上传运行目录、世界、日志全文或配置文件。`SHA256SUMS` 校验公开证据文件自身。

首次直接执行 gradlew 因文件没有执行权限返回 126；改用 `bash gradlew` 后 bot 编译成功，未改 wrapper 权限。脚本语法检查通过。既有 `gradlew.bat` 的 CRLF 修改不属于本任务，保留不动；全仓 `git diff --check` 因它报警，不掩盖该事实。

环境警告包括服务器离线模式/root 用户警告、Java native-access/Unsafe 弃用、库解析主机名失败后使用 localhost、flat 配置回退提示。它们保留在原日志；公开材料不包含私有主机名。版本过期提示并非 VeloZip 失败。主动断开附近若有 reset 也必须区分保活窗口内提前断线。

未覆盖：原生 26.2 bot、多人/长期负载、受限带宽或延迟、TCP 抓包、快速跨后端切换、热重载、极端关闭/超时交错。v1 没有独立双向切换屏障：后端替换入站后，代理尚未看到首个 VeloZip 帧前仍可能发出在途 vanilla 包；代理超时恢复 vanilla 与延迟到达的后端切换也可能交错。普通静止登录与有间隔重连没有穷举或修复这些竞态，不应据此宣称 v1 race-free。

矩阵结束后进一步加固夹具：启动时明确校验控制台 effective enabled/require/auth，防止错误路径导致假阳性；矩阵入口继续收集所有项但任何子项失败最终返回非零（最初矩阵入口自身返回 0 不代表全部子项通过，应以每项 JSON 为准）。公开 fixture 的脚本哈希指最终复现脚本；正式数据采集前后这些断言/汇总与配置路径变更已在本文披露，bot class 和插件 jar 全程未变。最终脚本还单独新跑禁用项验证配置断言，补充记录不计入 12 项主表。

本报告、实验夹具及上述脱敏材料一并提交到 GitHub；不上传原始运行目录、密钥、世界或完整环境日志，不打 tag 或发布 Release。
